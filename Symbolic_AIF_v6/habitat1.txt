  On the architectural question — pre-collection vs. current approach:

  This is a great observation. Here's an honest comparison:

  Current approach (online AIF):
  - 80 explore steps → only 4–10 of 64 slots fill → model has almost no scene
  map → navigation is essentially blind
  - The detector hasn't seen the apartment's objects from diverse viewpoints, so
  slots don't fire reliably
  - Each new episode starts cold

  Your proposed approach (offline pre-collection, like the toy env):
  - Run N episodes (say, 500) with random/systematic navigation from diverse
  start poses
  - Collect (RGB, depth, cam_to_world, GT pose, object detections) tuples
  exhaustively
  - Train WorldModelV6 on this dataset offline — slot attention, 3D object
  positions, belief updates all become well-calibrated
  - At test time the model immediately recognises objects and fills slots
  reliably from the first frame
  - Navigation then uses a warm, rich belief map rather than building it from
  scratch in 80 steps

  My honest assessment: The offline pre-collection approach is the right
  architecture for a real paper. It separates two distinct problems — learning 
  the object-centric world model vs. using that model for AIF navigation. Your
  toy environment worked well exactly because the model was pre-trained on
  exhaustive data. The current approach asks the model to do both simultaneously
  in 80 steps, which is too little.

  However, sticking with the current pipeline makes sense if the goal is to
  demonstrate zero-shot AIF with an untrained world model — which is a valid
  contribution but has a different framing.
